What Terax mode is inspired by Terax — the ~7MB all-in-one Agentic Development Environment Apache-2.0 · ~7.2k stars

How it works

A light all-in-one surface that fuses terminal, editor, an approval-gated AI agent, a git commit graph, and a web-preview pane into one quiet, fast room. The AI plans, edits via reviewed diffs, and reads a project-memory file (TERAX.md-style) before it acts.

Why it's good

strengths
  • All-in-one without bloat — terminal + editor + AI agent + git graph + web preview on one surface, kept light (Tauri-weight, OS WebView, no bundled Chromium).
  • AI is first-class AND safe — every edit is reviewed inline hunk-by-hunk and bash is approval-gated, so the agent can't silently mutate your repo.
  • Local-first & private — BYOK or fully offline, no telemetry, keys in the OS keychain, provider-agnostic (never locked to one vendor).
  • Fast by architecture — WebGL terminal stays silky at deep scrollback, sub-ms keystrokes, ripgrep search, ~300ms-class cold start.
  • Project memory baked in — a TERAX.md-style file + an /init scan means the agent starts every session already understanding the codebase.
  • Truly open & maintainable — Apache-2.0, active community; passes the independence bar.

Customize — the real knobs

  • Themes — pick a bundled UI theme or build a custom one in-app, plus an independent editor theme.
  • Background image with opacity + blur sliders.
  • Terminal — font family/size (8–32pt), letter spacing, scrollback depth (200–50,000 lines), and a WebGL/GPU render toggle.
  • Project memory — a TERAX.md-style file the agent auto-reads, plus an /init-equivalent that scans the workspace and writes the brief.
  • Agent personas — user-definable Coder / Architect / Reviewer with scoped tool subsets + global custom instructions.
  • Snippets and callable "skills" workflows.
  • Vim mode + dotfile import.
  • Provider choice — BYOK (OpenAI, Anthropic, Gemini, Groq, Grok, Cerebras, OpenRouter, DeepSeek, Mistral, any OpenAI-compatible endpoint) or fully local via Ollama / LM Studio / MLX.
  • Keybinding config file — a real user-editable dotfile (an Ursula addition — Terax has no documented one; see open question).
Extensions: full access This mode is a VS Code Profile sharing Ursula's one installed extension set (useDefaultFlags.extensions=true) — so all of these are available here and never removed on switch: Claude CodeKilo Codeany Open VSX extension Ursula's edge over real Terax: Terax ships no plugin/extension API at all — Ursula gives you Terax's diff-reviewed, approval-gated, project-memory agent feel PLUS a real extension host on top.

What Warp mode is inspired by Warp — the from-scratch Rust, GPU/Metal AI-native terminal with structured "blocks" blocks · structured-context agent

How it works

A block-structured terminal where each command + its output + exit code + timing is one discrete, addressable unit. The input line behaves like a real code editor, and the AI agent reads that structured terminal state to ground its suggestions. MCP servers are the official way to add tools, and reusable Workflows accumulate knowledge in place.

Why it's good

strengths
  • Blocks solve a decades-old pain — scroll to, select, copy, re-run, or share exactly ONE command's output without fishing through interleaved scrollback. One structural decision makes navigation, sharing, and AI context all cleaner.
  • The AI gets STRUCTURED context — blocks, branch, exit codes, history, recent I/O — not raw text, so the self-correcting agent is noticeably more accurate than an LLM bolted onto a normal terminal.
  • IDE-style input line — click to move the cursor and edit a long command like real text instead of fighting single-line readline.
  • Speed is measured — ≈1.9ms average redraw, 144+ FPS, so heavy output still feels instant.
  • Knowledge lives where the work happens — Workflows, Notebooks, and prompts stay in the terminal and sync, instead of rotting in a wiki.
  • Two clean AI modes — a quiet Terminal mode vs an Agent mode with model selection, autonomy level, and a conversation view; you stay in control of when it acts.
  • Sensible defaults, deep file-based config — usable day one, every surface (theme YAML, keybindings, prompt, launch configs, autonomy) editable and shareable as plain files.

Customize — the real knobs

  • Custom themes as YAML — 16 ANSI colors (normal + bright) plus accent/background/foreground in hex; Base16 supported.
  • Remappable keybindings/keysets saved to a keybindings file (Vim/emacs-flavored presets available).
  • Prompt — native Warp-style prompt with configurable "prompt chips" OR your own shell PS1 from .zshrc/.bashrc.
  • Launch configurations — saved window/tab/pane layouts + startup commands you relaunch as a unit.
  • MCP server registration — CLI-based servers Ursula launches/manages, or URL-based via Streamable HTTP/SSE with custom headers + env vars — the extension surface for the agent.
  • Reusable Workflows + interactive Notebooks/runbooks + shared prompts (a personal/team knowledge library).
  • AI configured independently from appearance — model choice, agent autonomy/permission level, default mode (Terminal vs Agent).
  • Warpify-style rules to extend the full experience into subshells/SSH (Docker, Python REPLs, remote sessions).
  • Block behavior (the core primitive) and the IDE-style input editor (multi-cursor, click-to-position, syntax highlighting).
Extensions: full access This mode is a VS Code Profile over Ursula's shared extension set (useDefaultFlags.extensions=true) — these are all present and never stripped on switch: Claude CodeKilo Codeany Open VSX extension The layering: real Warp has no UI-plugin marketplace — its only "extension" surface is MCP-for-the-agent plus file config. Ursula keeps that MCP surface AND adds a true editor extension host, so you get Warp's blocks and structured-context agent without Warp's terminal-only ceiling.

What Cursor mode is inspired by Cursor — the VS Code fork with editor-level AI sharing one codebase index editor-first · one shared index

How it works

An editor-first AI mode where inline edits, next-edit Tab completion, and an agent/composer panel all share ONE syntax-aware codebase index, steered by version-controlled project rules. Indexing is privacy-respecting (embeddings + obfuscated paths only) and model selection is user-controlled.

Why it's good

strengths
  • AI at the editor level, not an isolated chat sidebar — inline edit, next-edit Tab, and the composer share one index and one context system, so suggestions are repo-aware not file-aware.
  • Tab's next-edit prediction — predicting WHERE you'll edit next, not just completing the current line — is a genuinely distinct UX win.
  • Near-zero switching cost — imports settings, keybindings, themes, and extensions, so the AI is additive, not a replacement workflow.
  • Privacy-respecting indexing — store only embeddings + obfuscated paths, discard plaintext, Merkle-tree incremental re-indexing to stay fast on big repos.
  • Rules + MCP give clean, file-based ways to make the AI behave per project and reach external tools.
  • Model-agnostic — users aren't locked to one LLM vendor.

Customize — the real knobs

  • VS Code settings.json — imported on first run, fully editable.
  • Remappable keybindings with VS Code bindings as the baseline, including AI-specific actions.
  • Themes — import VS Code themes directly + install from Open VSX.
  • File-based rules mirroring .cursor/rules/*.mdc (glob-scoped, version-controlled) plus a global "Rules for AI" surface.
  • @-context symbols — @file, @folder, @Codebase, @Docs, @Web, @Git — to pin precise context into a prompt.
  • Per-chat / per-agent model selection (multi-vendor LLM routing).
  • MCP server configuration for custom tools/data sources.
  • Privacy Mode toggle controlling whether code/embeddings leave the machine.
Extensions: full access This mode is a VS Code Profile over Ursula's shared extension set (useDefaultFlags.extensions=true) — all available and never removed on mode switch: Claude CodeKilo Codeany Open VSX extension Ursula keeps Cursor's exact install paths — default the registry to Open VSX AND preserve all three VSIX sideload routes (Install-from-VSIX, drag-drop, --install-extension CLI) — so nothing on Open VSX is ever locked out by the install mechanism. Honest hard limit (same as Cursor's): MS-proprietary extensions (Pylance, official Remote-SSH, the C# debugger) are license-locked to Microsoft products and can't legally run regardless of mode — document open-source equivalents instead.

What Cate mode is inspired by CATE v1.1.1 — the Monaco-based, infinite-canvas, session-centric agent IDE Drey already runs spatial canvas · first-class sessions

How it works

A spatial mode where editor, terminal, browser, document, and agent-chat panels float and dock on an infinite zoomable canvas. Each agent run is a first-class restorable session, and a rich status bar turns invisible agent state into a live dashboard. The whole layout + sessions restore per project folder.

Why it's good

strengths
  • The canvas fits multi-agent work — humans reason about parallel runs better in 2D than in a tab strip; you SEE all sessions at once instead of cycling tabs.
  • Sessions are first-class objects — top session tabs + a left vertical list with flame icons and live/working/idle dots make "which agents are alive" a glance, not a hunt. The single biggest thing to replicate.
  • Deep run visibility — active model, context % meter, $ cost (this-chat + today), 5h and 7d reset timers, CLAUDE.md/rules/MCP/hook counts, an auto-mode toggle — turns invisible Claude Code state into a dashboard.
  • One unified theme recolors the ENTIRE surface (chrome + terminal + editor) from a single file, so the warm near-black + orange identity stays consistent.
  • Real node-pty terminals — zero emulation gaps; Claude Code, git, any CLI behaves exactly as native, and the status bar surfaces the project's Claude config.
  • Per-folder layout + session restore — reopen a project and the exact workspace returns.

Customize — the real knobs

  • Unified single-JSON theme — app chrome + full 16-color xterm palette + Monaco base/syntax tokens in one object, via a customThemes array + activeThemeId, validated against theme.schema.json, imported through Settings → Appearance → Import.
  • System light/dark auto-switch (systemLightThemeId / systemDarkThemeId) and a dedicated agent accent (agent-rgb / agent-light-rgb) so the AI presence is visually distinct.
  • Default identity — warm near-black surfaces with an orange #e0683c accent.
  • Editor/terminal — font size, minimap, terminal scrollback, contrast, cursor blink, optionIsMeta, auto-suspend idle terminals.
  • Canvas — grid style (lines/dots), snap-to-grid, auto-focus largest visible node, default panel size, zoom speed.
  • Workspace — default shell path, file exclusions, session order, recent projects, browser homepage/search engine, link open target.
  • Every keybinding rebindable; whole environment portable via one config.json.
  • Provider-agnostic agent — Anthropic-first plus Codex / Copilot / Gemini / OpenRouter / Groq / Mistral / DeepSeek, with per-chat model memory.
Extensions: full access This mode is a VS Code Profile over Ursula's shared extension set (useDefaultFlags.extensions=true) — all available and never removed on switch: Claude CodeKilo Codeany Open VSX extension Major upgrade over real Cate: Cate uses Monaco the engine but NOT the VS Code extension host, so it cannot load VS Code extensions at all. Ursula keeps Cate's canvas, first-class sessions, status-bar dashboard, and unified-theme feel WITH a full extension host behind it.

What Lite mode is a minimal, distraction-free baseline — the quiet end of the spectrum presentation change, not capability

How it works

A stripped-down visual mode: a clean editor + real terminal with the AI panels, canvas, status-bar dashboard, and block UI dialed down or hidden for focus and speed. It is a presentation/layout change only — capability is untouched.

Why it's good

strengths
  • Fast and distraction-free — minimal chrome means lower visual load and a snappier surface for focused editing or quick terminal work.
  • Nothing is actually removed — "lite" is purely a visual/layout choice, so you lose no capability by working here.
  • Lowest-friction entry point — a good default when you don't need canvas, blocks, or a full agent dashboard and just want to type and run.

Customize — the real knobs

  • Theme — the same unified theme system as the other modes; pick a minimal/low-chrome variant.
  • Editor + terminal essentials — font size, scrollback, minimap on/off.
  • Keybindings — the same rebindable, file-based config as every other mode.
  • Which AI surfaces are visible — collapse/hide the agent panel, status-bar dashboard, and block decorations for a quiet workspace.
  • Provider choice and per-chat model still available when you do invoke the agent.
Extensions: full access The key point for Lite: it is a VS Code Profile over the SAME shared extension set (useDefaultFlags.extensions=true) — these are present here too and never removed when you switch in or out: Claude CodeKilo Codeany Open VSX extension "Lite" trims visual chrome, NOT capability — no extension is ever removed when you enter or leave this mode.
